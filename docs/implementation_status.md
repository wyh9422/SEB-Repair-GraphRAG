## 验证证据

### 自动化测试

最终测试计数为 125 项：本地标准库环境通过 117 项、明确跳过 8 项科学计算集成测试；服务器 Python 3.12.3 的 125 项全部通过（约 4.91 秒）。82 个 Python 文件通过语法编译检查，`git diff --check` 通过。测试包括：

- CLI/QA 配置一致、空查询与空语料无模型调用、预构建结果跳过检索、第二轮文档/分数对齐、回放实际 judge 元数据。
- judge 异步失败不覆盖批首、非对象 JSON、空批次、请求配置记录。
- 多谓词/多来源、逆向探索、已暴露 ID 限制、分页、循环、非法动作、容量不足、最少来源覆盖。
- Agent 噪声种子、多分支、路径保护、各类预算、缓存用量、512+候选区域、轨迹篡改检测与重放。
- 真实 igraph 小图：适配结果与原 reset 权重公式/直接 PPR 一致；缺失实体不产生 NaN；非法图权重回退；Agent/Hybrid 最终证据完整；无回退时保留第一轮。
- 离线评估的分母、失败样本保留、回退用量去重、路径来源保留、缓存用量区别、配对统计与问题顺序校验。

命令：`python3 -S -m unittest discover -s tests -q`；服务器使用 `python -m unittest discover -s tests -q`。执行结果保存在服务器验证目录的 `validation_artifacts/unittest.log`。

### 真实索引与图缓存

在独立验证目录读取原服务器缓存，未覆盖原工程，也未重建 embedding：

- OpenIE：6,119 篇章、46,569 个实体、65,148 条规范化唯一事实；有效来源三元组 65,659 条，和原始未清理记录口径不同。
- 重复构建关系索引的 manifest 完全相同。
- 旧 igraph：52,689 个节点、778,347 条边；固定节点 reset 的 PPR 全部有限，分数和约为 1。
- 此数值检查不是基于真实问题 embedding 的数据集检索评测。

### 真实 API 冒烟验证

使用 `deepseek-chat` 和三篇合成文档的固定两跳问题，测试 Agent→judge→reader：

- Agent 成功提交一条两跳路径；3 次模型调用、3 次工具调用、2 条展开边、无重试或非法动作。
- 返回 Token 用量为 3,913 输入 + 275 输出 = 4,188，总耗时约 2.85 秒；这是本次单样例观察，不是平均性能或成本承诺。
- 不调用模型重放得到相同路径和篇章。
- judge 判定完整证据可回答；reader 返回预期的 `Lumen City`。

早先一次同类尝试出现 `APIStatusError`，未生成有效路径；恢复检查后最小请求与完整冒烟成功。未把失败记录当作成功样本，也没有通过更换检索方案规避失败。

运行脚本：`scripts/validate_agent_runtime.py`，仅显式 `--live` 才调用 API。结果保存在独立服务器目录 `/root/autodl-tmp/seb-agent-validation.Ujmpsx/validation_artifacts/`，其中 `runtime_summary.json` 为摘要，`live_agent_result.json` 为路径及轨迹。旧工程和其正在进行的任务未被替换或停止。

## 仍需后续实验确认

未运行完整数据集的四组配对效果实验，也未重新运行真实 embedding→全部查询检索→QA 的大规模流程。未验证所有可选离线后端组合。路径验证仅证明与索引及来源一致，不证明抽取事实真实；来源保留率不是语义路径正确率。当前评估的调用/Token/时间只覆盖轨迹已记录部分，不冒充完整系统账单。
